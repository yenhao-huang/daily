01. (speculative decoding) 釐清推測解碼的 KV commit／rollback 契約

原始議題 ↗

問題釐清

RFC 希望同一份模型能切換一般解碼與 tree／speculative decoding。候選 token 被拒絕後，KV 狀態必須保持正確；留言另提出 ring-buffer eviction、每層 head 數不同，以及 export-time 靜態 KV 量化的需求。

可能解法

建議先縮小到 SeqCache／TreeCache 的介面與正確性案例，驗證 propose、commit、分支遮罩與拒絕後續接。靜態 KV 量化如何參與 runtime 控制仍待 RFC 討論，不直接承諾整套跨 backend 實作。

應用場景

需要 EAGLE 類推測解碼、prefix 分支或 agent 工作流的桌面端 runner；RFC 提及 MLX、XNNPACK 與 Vulkan。切入點是契約與測試，硬體實作另議。

專有名詞介紹

KV cache：保留先前 token 的注意力資料。Commit／rollback：保留接受的候選、撤回被拒絕候選的狀態。Tree mask：限定每個分支可讀取的歷史。

RFC／未指派；有持續設計討論。需先與 RFC 參與者確認子範圍。02 / 21
