## NVIDIA Developer Blog

### Build Applications on NVIDIA BlueField Faster with NVIDIA DOCA Agent Skills

發布日期：2026-10-01

NVIDIA 發布 DOCA AI agent skills，將已驗證的 API 簽名、硬體能力需求與建置限制包裝成可供 agent 讀取的技能，涵蓋 Flow、GPUNetIO、PCC 與 RDMA 等函式庫。官方以 65 個實際開發提示進行比較，宣稱使用技能的 agent 達成全部檢核項目，而未使用者僅達 19%；示範中的 RDMA 應用也減少了手寫程式與硬體命令。

影響：讓 agent 取得具版本與硬體約束的機器可讀規格，可把「看似可行」的程式產出更早地轉成可驗證的基礎設施開發流程。

來源：[Build Applications on NVIDIA BlueField Faster with NVIDIA DOCA Agent Skills](https://developer.nvidia.com/blog/build-applications-on-nvidia-bluefield-faster-with-nvidia-doca-agent-skills/)

### Build Local AI Apps with C++ and NVIDIA TensorRT RTX Samples

發布日期：2026-10-01

NVIDIA 的 DIN Deploy 開源範例以 ONNX Runtime 搭配 TensorRT RTX execution provider，展示從 Hugging Face checkpoint 匯出 ONNX、再以原生 C++ CLI 部署到 Windows 或 Linux 的流程。範例涵蓋 Whisper、Parakeet、Nemotron 串流 ASR、SAM 2.1 與 FLUX.2，並以量化和 Vulkan／DirectX 互通降低整合門檻。

影響：以共通 ONNX Runtime API 隔離模型轉換與應用程式邏輯，能讓本機 AI 產品較容易跨硬體與平台維護加速路徑。

來源：[Build Local AI Apps with C++ and NVIDIA TensorRT RTX Samples](https://developer.nvidia.com/blog/build-local-ai-apps-with-c-and-nvidia-tensorrt-rtx-samples/)

## Google Research

### Toward provably private learning from federated data

發布日期：2026-10-02

Google Research 發表新一代聯邦學習系統，以可信任執行環境（TEE）把資料處理移到伺服器端，同時維持可外部驗證與稽核的匿名化保證。裝置會加密上傳資料並預先授權允許的 TEE 工作負載；KMS、公開透明度日誌與可重現建置讓審計者能檢查實際可存取資料的程式，Gboard 已採用該系統。

影響：聯邦學習的差異化不再只在於資料不離開裝置，還在於能否對伺服器端訓練提出可驗證的隱私與治理證據。

來源：[Toward provably private learning from federated data](https://research.google/blog/toward-provably-private-learning-from-federated-data/)

### A model guide for the GPT-6 family

發布日期：2026-10-02

OpenAI 發布 GPT-6 系列實務指南，將模型選擇、推理強度與速度取捨連到不同工作負載，並建議以快取、context compaction、監控與資料控制管理正式環境的成本與可靠性。指南也聚焦長時間任務：以明確交付條件、技能與儲存庫指示、steering、非同步工具及可獨立進行的工作，讓 agent 在持續執行時仍可控。

## Apple Machine Learning Research

### How Much of a Harness Does a Strong Agent Need for Autonomous ML Engineering?

發布日期：2026-10（官方頁面僅提供月份）

Apple ML Research 刊出研究，評估自主機器學習工程 agent 是否需要複雜的多 agent 編排、檢索子 agent 與其他 scaffolding。該研究在相同時間預算與相同前沿 LLM backbone 下，比較多個開源先進 harness，發現它們沒有優於具讀寫與 shell 基礎工具的最小化 coding-agent session。

影響：對現階段 MLE benchmark 而言，模型能力與直接執行環境的品質可能比堆疊更多編排層更值得優先投資。

來源：[How Much of a Harness Does a Strong Agent Need for Autonomous ML Engineering?](https://machinelearning.apple.com/research/harness-autonomous-ml-engineering)
