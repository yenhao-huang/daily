## NVIDIA Developer Blog

### NVIDIA Open Agent Safety Platform: A Reference for Continuous In-Silicon Agent Monitoring

發布日期：2026-09-28

NVIDIA 發表 Open Agent Safety Platform，將 OpenShell 的開源沙箱執行期與 BlueField-4 DPU 上的 NVIDIA Sentry 結合，形成從軟體到硬體的分層代理安全架構。它強調可驗證政策、帶外強制執行，以及讓 DPU 成為模型存取路徑上的持續可觀測與即時政策執行點。

影響：企業部署長時間運作的代理時，可把權限與工具存取的安全控制移出代理本體，降低單靠提示詞或應用程式內控管的風險。

來源：[NVIDIA Open Agent Safety Platform](https://developer.nvidia.com/blog/nvidia-open-agent-safety-platform-a-reference-for-continuous-in-silicon-agent-monitoring/)

### Add Runtime Controls to AI Agents with NVIDIA OpenShell

發布日期：2026-09-28

OpenShell 0.1.0 提供開源執行期，透過沙箱、受控服務存取、憑證保護與形式化政策分析，限制代理能接觸的系統、資料與 API 操作，不必重寫既有代理。其 Gateway、Supervisor 與 Sandbox 元件可管理代理群、檢查對外請求，並以核心層級機制約束檔案、程序與網路行為。

影響：這讓代理框架在保有工具使用彈性的同時，能在工作負載外強制實施最小權限，特別適合有敏感憑證或生產 API 的場景。

來源：[Add Runtime Controls to AI Agents with NVIDIA OpenShell](https://developer.nvidia.com/blog/add-runtime-controls-to-ai-agents-with-nvidia-openshell/)

### How NVIDIA DSX MaxLPS Maximizes AI Factory Throughput and Efficiency

發布日期：2026-09-27

NVIDIA 說明 DSX MaxLPS 如何在固定電力預算內動態重分配閒置功率；與 Nscale 的 GB300 NVL72 測試把受管 GPU 數從 140 提升至 192，在相同 264.4 kW 預算下使彙總吞吐量提高 49.2%。測試同時顯示中位與 P75 延遲接近基準，但 P99 首 token 時間增加 17%，凸顯容量增益仍需配合尾端延遲評估。

影響：資料中心的競爭重點正從單卡效率延伸到全廠功率協調；採用前應以真實工作負載驗證功率政策與延遲目標。

來源：[How NVIDIA DSX MaxLPS Maximizes AI Factory Throughput and Efficiency](https://developer.nvidia.com/blog/how-nvidia-dsx-maxlps-maximizes-ai-factory-throughput-and-efficiency/)

發布日期：2026-09-28
